## Prior finding dispositions

### P2-1 — Async disposal and natural-end cleanup: RESOLVED

- `WebAudioEngine.start()` creates an `AbortController`, passes its signal to the audio request, and checks that the same context is still active after resume, fetch, decode, and renderer loading (`apps/web/src/demo/audioEngine.ts:44-65`).
- `dispose()` sets the terminal status before aborting pending work, stopping/disconnecting any source, closing the context, and clearing every retained clock/resource field (`apps/web/src/demo/audioEngine.ts:116-140`). A disposed start therefore cannot recreate or schedule a source after an asynchronous boundary.
- The source-owned ended handler finalizes the source and context before notifying React (`apps/web/src/demo/audioEngine.ts:69-105`). Natural completion no longer leaves a running context or scheduled clock behind.
- Regression tests cover natural completion cleanup and idempotent disposal during a pending request, including request abortion, terminal status, context closure, and prevention of source creation (`apps/web/src/demo/audioEngine.test.ts:69-121`).
