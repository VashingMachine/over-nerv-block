### P3 — responsiveness/cancellation E2E is partially masked by visible dwell

The production component keeps analysis visible for at least 500 ms. The heartbeat counts total ticks until the result appears, and cancellation starts as soon as progress is visible. A fast worker can finish before either assertion while the UI is satisfying the dwell.

Static architecture and boundary tests establish worker isolation and termination, so this does not block Sprint 04. A later hardening pass should measure heartbeat gaps during actual worker progress and prove real-worker cancellation while processing remains in flight.

### P3 — runtime worker error whitelist is broader than the protocol

Runtime error validation currently checks the combined boundary-message map, including main-thread-only codes such as `analysis_too_large`, while the TypeScript worker protocol excludes them. The typed worker cannot emit those codes and every such response still settles and cleans up, so this is nonblocking. A separate runtime worker-code whitelist would make validation exact.
