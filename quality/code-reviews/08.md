## Resolution of former P2 findings

### Resolved — only an actual worker error event or attempt timeout retries

Retryability is now an internal property of `WorkerAttemptFailure`, separate from its public boundary code (`apps/web/src/analysis/workerBeatAnalyzer.ts:58-78`). Channel cloning, progress-callback, posting/setup, malformed-response, and worker-declared error paths are terminal. Only `handleWorkerError` and `handleTimeout` construct a failure with a retry cause (`workerBeatAnalyzer.ts:218-224`), and the outer loop retries only when that internal cause is present (`workerBeatAnalyzer.ts:390-401`).

Focused tests prove worker crashes and timeouts create at most one fresh retry, while channel-clone, posting, and progress-callback failures create one worker only and clean their resources (`apps/web/src/analysis/workerBeatAnalyzer.test.ts:330-366,391-489,531-557`).

### Resolved — checkpoint validation rejects unknown nested data

The quality-grid object and every nested object stored within it are now strict: confidence, beat, tempo candidate, baseline comparison, and the grid itself (`packages/chart-schema/src/index.ts:207-254`). Because `beatGridCheckpointSchema` embeds that strict grid (`index.ts:442-450`), raw recovery records cannot be silently sanitized while private or runtime fields remain durable.

Schema tests reject unexpected fields at the checkpoint, grid, confidence, tempo-candidate, comparison, and beat levels (`packages/chart-schema/src/index.test.ts:599-685`). Recovery-store tests additionally prove invalid top-level, grid-level, and nested-beat records are discarded and deletion is attempted (`apps/web/src/recovery/beatGridRecoveryStore.test.ts:117-166`). The store still never returns invalid data when cleanup itself is denied (`beatGridRecoveryStore.test.ts:168-176`).

### Resolved — denied Forget remains visible and retryable

`forgetRecoveredGrid()` now leaves the recovered grid in state until IndexedDB deletion returns `cleared`. An unavailable deletion sets the explicit `forget_failed` status instead (`apps/web/src/localAudio/LocalAudioPicker.tsx:483-499`), whose copy says the checkpoint is still saved and invites retry (`LocalAudioPicker.tsx:200-222`). The Forget button is disabled only while deletion is in flight, so it becomes retryable after failure.

The component regression test proves a denied deletion keeps the recovered workspace visible, re-enables Forget, preserves the separate correction record, and permits a subsequent successful retry (`apps/web/src/localAudio/LocalAudioPicker.test.tsx:969-1013`). Generation guards and the shared recovery write queue continue to prevent stale delete results from overwriting a newer completed analysis.
